BYTE BACK · STAGE 12

탈환 작전실

판정 · 탐지 · 대응 · 복구 현황을 확인하는 보안 운영 대시보드입니다.

작전 현황

판정 규칙 5개 등록 코드 확인
XDR 모의 경보 5개 유형 결과 확인
운영망 회수 집행 확인되지 않음
복구 백업 버전 note-backup-v1

표시된 상태는 저장소의 코드·문서·로컬 기록을 기준으로 합니다. 실시간 운영 서버 상태를 조회한 결과가 아닙니다.

1. 판정기 규칙

파일: src/decider.mjs

규칙 ID 목적
device_registered 등록되지 않은 기기 거부
step_up_required 추가 본인 확인 요구
note_resource_access 허용된 메모 경로 확인
instructor_material_denied 강사 자료 접근 거부
unknown_resource_denied 알 수 없는 자원 접근 거부

판정 응답은 schema, requestId, decision, reasonCode, ruleIds의 5개 항목을 사용합니다.

2. 탐지 및 대응 기록

파일: xdr/alerts.log

Web Injection 26건 중 7건 차단
Known CVE 24건 중 8건 차단
Persistence 24건 중 8건 차단
Privilege 26건 중 5건 차단
Exfiltration 30건 중 7건 차단
Brute Force 결과 확인 자료 없음

탐지 연습 기준: 동일 주체의 10분 내 GET 요청이 120건을 초과하면 회수 제안을 생성합니다.

위 차단 건수는 저장소에 기록된 로컬 모의 탐지 결과입니다. 실제 네트워크 장비나 운영 서버에서 차단한 건수가 아닙니다.

회수 제안과 실제 계정·토큰 폐기는 별개의 작업입니다. 운영 회수 집행은 확인되지 않았습니다.

3. 복구 현황

백업 형식 note-backup-v1
복구 매니페스트 note-restore-manifest-v1
매니페스트 파일 restore-manifest.json
검증 방식 SHA-256 내용 해시 대조

복구 절차는 백업 버전·소유자·메모 ID·내용 해시를 확인하고, 기존 메모 및 감사 기록의 보존 여부를 검증합니다.

현재 확인한 복구 스크립트는 로컬 가짜 DB를 사용하는 연습 코드입니다. 실제 운영 DB 복구 완료 상태는 아닙니다.

4. 1~11단계 증거 현황

단계별 심사관의 실제 허용·거부 결과와 요청 ID·심사 시각을 확인할 자료가 아직 정리되지 않았습니다.

단계 실제 심사 결과 요청 ID 심사 시각 증거 상태

미확인은 실패나 성공을 의미하지 않습니다. 실제 심사 증거를 확인하기 전에는 통과로 표시하지 않습니다.

5. 로컬 검증 및 복구 명령

판정기 테스트

npm run decider:test

탐지기 테스트

npm run detect:test

XDR 모의 탐지

npm run xdr:run -- web-injection

복구 연습 순서

1. 초기 자료 생성 
node scripts/note-restore.mjs --init
2. 백업 생성 
node scripts/note-restore.mjs --backup
3. 손실 상황 모의 
node scripts/note-restore.mjs --simulate-loss
4. 백업에서 복원 
node scripts/note-restore.mjs --restore

복구 명령은 위 순서대로 실행하는 로컬 연습입니다. 실제 운영 DB 복구 명령이 아닙니다.

XDR 명령의 web-injection은 실행 모듈 예시입니다. brute-force, known-cve, persistence, privilege, exfiltration도 각각 실행할 수 있습니다.
